# SHAP + LLM Explanation Outputs

This folder contains the saved outputs from `notebooks/04_llm_explanation_layer.ipynb`.

## Output files

- `threshold_policy_table.csv` — precision, recall, confusion counts, review workload, review rate, and missed-fraud amount across tested Random Forest thresholds.
- `precision_recall_by_threshold.png` — precision and recall across the tested thresholds.
- `review_workload_by_threshold.png` — number of transactions sent to manual review across thresholds.
- `flagged_transactions.csv` — the 50 highest-scoring test-set transactions with fraud score >= 0.30 selected for the explanation stage.
- `flagged_transaction_explanations_input.csv` — compact explanation inputs containing transaction ID, amount, fraud score, review decision, selected threshold, and the three strongest positive local SHAP contributions.
- `analyst_explanations.csv` — 10 analyst-facing notes generated by the OpenAI model from the verified explanation inputs.
- `llm_explanation_faithfulness_review.csv` — simple rule-based checks for the 10 generated notes. The checks verify score, threshold, and feature-name presence and flag selected unsupported real-world terms.
- `project_summary.txt` — short summary of the saved notebook run.

## Important limitations

The Kaggle features `V1`-`V28` are anonymized. SHAP values show how those model inputs contributed locally to a prediction, but they do not reveal real-world meanings such as merchant identity, device, cardholder identity, or location.

The rule-based faithfulness check is intentionally narrow. Passing it means the generated note contains the expected model evidence and avoids a small list of unsupported terms; it is not a guarantee that the explanation is fully correct or production-safe.

The threshold analysis is exploratory and uses the held-out test split in this project. A production workflow should tune the threshold on a separate validation set and reserve an untouched test set for final evaluation.
